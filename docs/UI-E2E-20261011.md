# UI and runtime end-to-end audit, 2026-10-11

The audit was requested after early network confirmation clicks failed and red
notices appeared across unrelated pages. All source, regression tests, helpers
and documentation changes are in this Git checkout. Private configurations,
credentials, phone numbers, SMS contents and private screenshots are excluded.
Real voice tests were authorized on an ordinary inexpensive SIM.

## Reproduced defects and corrections

1. **Early Confirm connection returned HTTP 409.** Control now exposes network
   readiness, rollback progress and the remaining confirmation window. Confirm
   stays disabled while applying/restoring. Save and Scan stay disabled until
   the transaction ends; polling cannot re-enable a busy action. Confirm and
   Roll back also remain mutually blocked until their in-flight request finishes.
2. **Successful rollback became a persistent red error on unrelated tabs.**
   Manual and timed successful restoration are informational. Actual connection
   or restoration failures remain visible on Status/Mobile/Wi-Fi/Network.
   Restoration errors are checked. An unchanged Wi-Fi connection is retained,
   and automatic rollback reloads restored fields while preserving other drafts.
3. **A delayed worker could apply an already rolled-back profile.** The worker
   checks its transaction token after acquiring the network lock. A regression
   executes the real delayed worker after cancellation and after replacement by
   another transaction. Neither abandoned profile may touch the new transaction.
4. **Unrelated Save could discard the SIP client binding or other drafts.**
   Save collects only the current Mobile/SIP/Wi-Fi/Network section. Malformed
   hidden drafts do not prevent saving another page. SIP is reloaded only when
   its settings or effective SERVER bind address change. Mobile, DNS and Wi-Fi
   changes retain an unchanged listener and registered client.
5. **Status could claim voice readiness in Disabled mode or during a switch.**
   Disabled is now explicit in Mobile, Status and the header. An accepted mode
   change waits for the matching runtime mode before displaying readiness. PBX
   registration failures display the actual SIP result instead of registering
   indefinitely. Error punctuation after Wi-Fi restoration is corrected.
6. **Saving SSH failed because runtime dependencies were missing.** Restored
   only the missing checked Dropbear/shell files and exact symlinks. A different
   installed executable is never replaced by this recovery helper.
7. **GSM CS remained at Starting CS voice.** Cellular registration succeeded,
   but the preserved driver rejected the extended RESUME format. The native
   controller now sends the original three-field command, which the new driver
   also accepts with GSM as its default. A native-only update restored readiness
   on the existing driver. No driver, PCM, IMS media/gain/CMR or SIP codec change.

## Reproducible validation

Run all operations from the repository root:

```sh
make test package package-check audit
make task TASK=test-ui-e2e-server.py ARGS='--timeout 12'
make task TASK=ui-e2e-device.py ARGS='--assets --call-stats --cs-diagnostics --network-policy' SERIAL=... ADB=...
make task TASK=ui-e2e-api.py SERIAL=... ADB=...
```

`ui-e2e-api.py` prompts without echo, reports sanitized facts and does not submit
SMS/calls. Explicit `--pbx-registration`, `--administrator-password`,
`--ssh-password` and `--hotspot-settings` modes mutate real settings and need
authorized scope. Each saves a protected backup and restores its profile. The
PBX test requires the dedicated password-free local MF79U provider; SSH rotation
requires the already built runtime and Paramiko.

`install-ui-dependencies.py --restore-missing` repairs only missing checked SSH
files. `install-native-update.py --install` updates only the native controller
after checking idle state, running executable, supervisor ownership, staging
space and backup checksum. It preserves boot/settings/CS/SIP/IMS binaries and
requires fresh client registration afterwards. Run through `make task` only
after `make test-native build-native`; it does not replace the overlay installer.

Full isolated validation passed: 26 native C fixtures, four Python regressions,
Go/JS/SIP/RTP suites, workflow failure guards, package and publication/secret
checks. Native/adapter lifecycle tests were rerun after CS compatibility changes;
Go/JS/package/audit after the early rollback cancellation fix. Generated logs,
dated device/API receipts and safe screenshots stay under ignored `reports/`;
backups stay in ignored `private/backups/` with restrictive permissions.

Remaining coordinated checks are outgoing conversations, fresh call/audio in
each remaining mode/direction/PBX combination, an available Wi-Fi AP plus station
DHCP, and live TCP/TLS/codec negotiation. The user requested outgoing calls later;
no additional unattended call or repeat SMS is armed.
